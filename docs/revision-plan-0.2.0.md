
# GlassDesk 修订计划：计划 1 收尾、视觉重构与本地插件

> 保留最初计划作为决策记录。陪伴位置、尺寸、表情节奏和播放器时间布局已按用户后续要求修订，以 [播放器修订](player-adjustments-review.md) 为准；最终本机证据与仍未验证的指标/环境见 [验收报告](test-report.md)。本页的初始规格不覆盖后续明确指示。

## 1. 目标、当前完成度与交付范围

本次在现有 GlassDesk 工程上迭代，目标版本为 **0.2.0**。先修正基础缺陷，再完成视觉原型、真实音频和插件，最后对同一发布版本统一验收。只使用 GlassDesk 自身代码及明确授权的参考资料，不读取或复用工作区其他项目代码。

产品仍面向长期自用和朋友试用。核心验收标准是：**界面有明确视觉中心，材质精致，动画连贯，日常驻留可靠。**

依据[计划 1 原文](<D:/Believe_in_yourself/about AI/work about agents/codeX/codeX work/GlassDesk/docs/original-plan.md>)及当前证据，完成度如下：

| 项目 | 当前结论 | 本次处理 |

| 网易云歌曲、歌手、封面与基础控制 | 有历史实机读回证据 | 对最终版本重新验证 |

当前[状态机](<D:/Believe_in_yourself/about AI/work about agents/codeX/codeX work/GlassDesk/src/GlassDesk.Core/WidgetController.cs:99>)存在一个明确遗漏：全屏临时唤出会清除原先的手动隐藏状态。必须改为两种状态独立管理：

- 普通场景：可见性由手动显示／隐藏决定。
- 开启全屏避让时：可见性由此次全屏的临时唤出状态决定。
- 全屏热键只改变临时状态，不修改原先手动状态。
- 退出全屏清除临时状态，恢复原先手动显示／隐藏规则。

旧[能力矩阵](<D:/Believe_in_yourself/about AI/work about agents/codeX/codeX work/GlassDesk/docs/capability-matrix.md>)作为历史参考，不能代替最终版本验收。

本次包含视觉重构、暂停五秒切时钟、内置真实音频波浪条、完整本地功能插件系统、原创陪伴球和液态玻璃。歌词、收藏、天气、完整月历、角色成长、实际换装内容及插件市场仍不进入本版。

## 2. 视觉、布局与动画规格

### 视觉方向

采用白色半透明磨砂玻璃、细亮边、低对比阴影和克制的层次。Mac 风格主要通过比例、曲率、排版和动作连续性体现。

- 间距统一使用 4／8／12／16／24 DIP。
- 字体使用 Windows 系统字体；主要字重为 400／500／600。
- 时间使用等宽数字特性，默认 `HH:mm`，不显示秒。
- 日期和星期合成一条次要信息，避免拆到胶囊两端。
- 去掉重复的“播放中”、无明确作用的绿点和装饰省略号。
- 基础模糊默认沿用 20 DIP，白色染色默认沿用 0.62，统一管理材质参数。
- 控件通过细边、轻阴影和按压反馈形成层次，避免堆叠高光和大面积黑色按钮。

以下是原型的固定起始规格；完成一次具体视觉审阅后冻结尺寸和比例：

| 形态 | 初始尺寸，DIP | 布局与视觉中心 |
|---|---:|---|
| 时钟胶囊 | 200 × 52 | 时间与日期作为一组居中；陪伴球位于左侧次要槽位 |
| 音乐胶囊 | 208–296 × 52 | 左侧小球、中间歌曲与歌手、右侧真实波浪条；宽度仅在歌曲内容变化时测量 |
| 时钟小展开 | 240 × 144 | 居中的时间为唯一主角；日期与连接操作降低层级 |
| 音乐小展开 | 320 × 148 | 56 DIP 封面与歌曲信息组成上方主信息组；下方播放控制整组居中 |
| 时钟大展开 | 280 × 232 | 大时间、日期和简洁连接入口；通过较小高度减少空白 |
| 音乐大展开 | 320 × 440 | 192 DIP 居中封面、歌曲信息、对称控制及真实可用进度 |

音乐胶囊默认不同时放置封面和小球；关闭陪伴插件后，音乐胶囊使用小封面，时钟胶囊重新居中，不留下占位空洞。小展开中的小球放在右上角，详情页放在顶部左侧，尺寸为 20 DIP；胶囊中为 24 DIP。

窗口展开保持水平中心和顶部锚点，靠近工作区边缘时向内调整。大展开空间不足时只滚动内容，关闭和播放控制保持可达。

### 设置界面

采用悬浮分段标签：**外观／交互／陪伴／插件／通用**。

- 标签共用一个移动选中底板，切换时保持空间连续。
- 首选窗口尺寸 880 × 640 DIP，并限制在当前工作区内；最小尺寸也必须服从较小工作区。
- 内容最大宽度 640 DIP，左右居中，使用有限宽度布局。
- 设置行采用文字 `Star`、操作控件 `Auto`；窄窗口或文字放大时，操作控件换到下一行。
- 页面只允许纵向滚动。滑块、开关、快捷键清除和连接按钮不得越过视口。
- 减少大标题和无意义留白；拖动标题栏区域避开标签与按钮。
- 保留实时保存、显示／隐藏、启动项、快捷键、连接说明和诊断入口。

### 动画与曲线

沿用统一 MotionController，保留当前姿态与速度，重定向从当前状态继续。输入在动画过程中始终有效。

| 动作 | 默认时长 |
|---|---:|
| 按压反馈 | 80ms |
| 标签底板移动／内容切换 | 180ms／140ms |
| 胶囊→小展开 | 220ms |
| 小展开→大展开 | 260ms |
| 胶囊→大展开 | 280ms |
| 收回胶囊 | 180ms |
| 时钟／音乐内容替换 | 160ms |

外壳尺寸、圆角、内容透明度及共享元素使用同一动作进度。文字在实际 DPI 下清晰绘制，不随整张位图拉伸；窗口命中区域跟随当前呈现姿态。

优先排查整数窗口区域对 Composition 抗锯齿边缘的裁切。视觉边界使用浮点几何；窗口区域保留必要的物理像素余量，再通过真实跨进程点击验证四角与阴影穿透。不能只凭截图判断穿透成立。

减少动画时直接切换到清晰目标状态。静止界面停止动画循环，不增加持续漂浮或反复弹跳。

## 3. 功能、技术接口与插件

### 技术基线与暂停规则

保留 **C#、.NET 10、WinUI 3、Composition 和薄 C++ 原生层**。沿用已锁定工具链，不迁移到 Qt 或 WebView。设置与原生组件分别管理各自的合成对象。

新增三个基础抽象：

- `CapsuleContentMode`：独立决定胶囊展示时钟还是音乐。
- `WidgetLayoutMetrics`：统一提供当前形态、内容和插件槽位对应的尺寸，替代散落的固定尺寸。
- `IAudioVisualizationSource`：输出来源状态、会话标识、单调时间戳、RMS 和频段数值。

暂停五秒规则如下：

| 情况 | 行为 |
|---|---|
| 正常播放 | 胶囊显示音乐 |
| 刚进入暂停 | 从真实暂停状态建立单调时钟起点 |
| 暂停达到 5,000ms | 仅胶囊内容切为时钟 |
| 此时处于小展开／大展开 | 保持原音乐内容；以后收回胶囊时显示时钟 |
| 恢复播放 | 取消暂停计时，胶囊立即恢复歌曲内容 |
| 重复暂停通知、封面刷新 | 不重置计时 |
| 暂停期间同一会话切歌 | 更新真实元数据，不重置暂停计时 |
| 会话替换 | 根据新会话状态重新建立计时 |
| 隐藏后再次显示 | 根据实际经过时间决定内容，不重新等待五秒 |

不改变真实 `MediaSnapshot`，不伪造断开状态，不清除封面、控制能力或时间轴。关闭、停止、切换等其他状态沿用现有规则。

时钟只在分钟边界、日期变化、系统时间／时区变化和重新显示时刷新，避免当前每秒刷新整套内容的开销。

### 内置真实音频波浪条

波浪条属于主程序，默认开启，并在外观设置中提供独立开关。

使用 Windows 进程级 WASAPI loopback，只采集已识别网易云进程及其子进程的播放输出。[Microsoft 进程音频采集示例](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)

- 单独实现媒体来源到客户端 PID 的匹配；覆盖客户端重启、多实例及进程树变化。
- 无法可靠识别来源时显示不可用，不回退为全系统音频采集。
- 原生层负责采集，托管层使用可复用缓冲区计算 RMS 与 FFT。
- 分析频率为 20–30Hz，显示 6–8 个频段，通过 Composition 平滑插值。
- 暂停、隐藏及没有可见波浪条时停止采集和分析。
- 不采集麦克风，不保存或上传原始音频。
- 来源无音频或采集失败时安静归零，不能使用随机波动冒充真实频谱。
- 目标端到端响应延迟不超过 150ms。
- 音频频谱不能用于推断歌曲总时长或补造播放进度。

### 完整本地功能插件系统

插件由你维护，通过随安装包附带或本地导入分发。没有在线下载、上传、插件市场或后台服务；不设置系统强制断网。

插件采用可信 C# **进程内加载**，每个插件独立 AssemblyLoadContext，共享契约和框架程序集由默认上下文持有。[Microsoft AssemblyLoadContext 文档](https://learn.microsoft.com/en-us/dotnet/core/dependency-loading/understanding-assemblyloadcontext)

最小接口包括：

- `IGlassDeskPlugin`：初始化、注册贡献、启动、暂停、停止和释放。
- `IPluginContext`：读取场景与媒体状态、访问插件配置、提交 UI／渲染请求及注册操作。
- 内容页、交互命令、设置、角色和材质贡献接口。
- `ICompanionAppearance`：将角色外观与表情、动作状态分离，供以后换风格使用。

本版保持一个主组件。功能插件可以向详情页工具入口注册内容页和操作，不限定为换皮插件；窗口、布局、输入、动画调度及焦点规则仍由宿主统一管理。

本地插件包包含标识、名称、版本、API 版本、入口程序集／类型、资源和资源开销说明。包格式为 `.glassdesk-plugin`；宿主检查路径、重复标识及兼容性后安装。同一标识更新替换旧版本，保留配置。

用户开关 `Enabled` 与运行状态独立。隐藏时暂停工作不等于关闭插件。关闭插件必须取消任务、撤销事件、移除视觉贡献并释放资源；无法可靠卸载的原生组件在更新／移除时要求重启。

可捕获的插件异常停止该插件贡献并回退，保留主程序音乐功能。进程内插件不是安全沙箱，不能承诺隔离原生崩溃。GPU 策略不得自动改变用户的插件开关。

首次安装及旧版升级的默认值：**陪伴球开启，液态玻璃关闭**。每个插件显示独立开关和实测资源说明。

### 原创陪伴球插件

实现原创黑色圆球、两只眼睛与轻微形变，内部使用独立设计的矢量几何。提供平静、好奇、开心、困倦、惊讶、眨眼六类表情。

- 默认每 8 秒随机切换，避免连续重复。
- 表情转换约 180–240ms，可被新状态打断。
- 使用克制的眨眼、眼睛位移和形变，不持续弹跳。
- 隐藏时暂停表情计时，恢复时避免补播积压动画。
- 设置支持球体颜色，眼睛自动选择清晰的深／浅颜色。
- 预留外观接口，本版不显示尚未实现的换装功能。

参考仓库声明其素材仅供学习、不得商业使用或再分发，因此本版不使用其中的角色路径、几何数据或提取素材。[Grok 参考仓库说明](https://raw.githubusercontent.com/blessonism/grok-icon-study/main/README.md)

### 液态玻璃插件

首版作用于桌面组件外壳。使用独立 D3D11／HLSL 实现轻微边缘折射、细反光及凸面明暗；文字、封面和按钮保持清晰，不随玻璃扭曲。

背景采样路线固定为 **Windows Graphics Capture 显示器纹理 → GPU 裁剪 → 模糊与折射 → 原生宿主合成**。

现有 HostBackdropBrush 不能读回像素，不能直接当作自定义折射纹理。[Microsoft HostBackdropBrush 说明](https://learn.microsoft.com/en-us/uwp/api/windows.ui.composition.compositor.createhostbackdropbrush?view=winrt-26100)

- 开启液态玻璃时，对主体和阴影采用经验证的采集排除机制，避免采样自身产生反馈。
- 你已接受优先保证真实折射：开启后，组件可能不出现在外部截图或录屏中。
- 关闭插件时恢复原先的窗口采集属性。[Microsoft 窗口采集排除接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)
- 后处理只处理组件周围的必要区域，默认上限 30Hz；形状与交互继续平滑呈现。
- 纹理保留在 GPU；正常渲染不进行持续 CPU 像素读回。
- 显示器采集自身可能仍有整屏开销，必须单独测量。
- 隐藏时暂停采集。采样失败、设备失效或环境不支持时回退基础磨砂，保留用户启用状态并显示原因。
- 技术原型必须证明真实背景变化、无自身反馈、正确 DPI 和可靠释放；普通透明渐变不能作为完成证明。

[QtGlassFlow](https://github.com/SuperSiyer/QtGlassFlow)采用 GPL-3.0，且示例背景可以来自图片。借鉴其材质视觉与通用图形原理，独立实现本项目渲染，不复制或机械翻译其着色器，也不引入 Qt 依赖。

## 4. 执行顺序与协作

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| P0：基线与计划 1 收尾 | 固定源码和二进制批次；修复全屏手动隐藏遗漏；分析较新驻留增长；验证音频采集与液态背景路线 | 基础问题有明确结论，技术原型真实可运行 |
| P1：视觉原型 | 实现六种内容／形态组合、浮动标签、核心动画和曲线修复 | 提供真实背景上的静态对照与可操作原型，集中完成一次视觉审阅 |
| P2：核心集成 | 接入新尺寸模型、暂停五秒策略、真实波浪条及完整插件契约 | 数据、形态、输入和计时规则通过检查 |
| P3：插件集成 | 完成陪伴球、液态玻璃及各自设置和资源释放 | 两个插件可独立启停，功能贡献接口也经过验证 |
| P4：统一验收与发布 | 真实场景、驻留、帧率、安装升级卸载及配置迁移 | 所有结论对应最终发布版本，报告与包一致 |

P1 视觉未通过前不扩大视觉功能。音频和插件基础设施可以继续独立开发；小球和液态玻璃按最终视觉规范集成。

执行会话允许使用子智能体。接口冻结后分为原生宿主／液态材质、视觉／设置、音频／媒体、插件生命周期四类任务；主智能体负责 Core 状态规则、集成和最终验收。GUI 操作由单一智能体统一执行，避免同时操作桌面或修改同一视觉模块。

配置升级到版本 2，保留位置、延迟、快捷键、启动项及已有外观偏好，新增波浪条和插件设置。常规安装器保持当前用户、自包含安装、原 AppId 和配置保留规则，版本统一更新为 0.2.0。

当前环境的 Platform 普通构建曾返回失败但没有编译错误，单进程构建后通过。执行核验沿用 `-m:1 -p:BuildInParallel=false`，记录环境限制，不把它误报成源码测试失败。

## 5. 验收、交付与参考使用

| 分类 | 必须覆盖 |
|---|---|
