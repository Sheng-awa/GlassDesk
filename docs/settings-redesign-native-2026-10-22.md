# 原生设置 UI 改版 · 2026-10-22

## 2026-10-23 原文件修订（当前有效）

本节取代下方 10 月 22 日记录中的“五分类不变、平面轻分隔、不改字体 ABI、未取得截图”等旧结论。按用户要求直接修改真实源码，覆盖原来的 settings-redesign-2026-10-22 程序目录；没有新增版本目录、HTML 或另一份设计计划。

- 修正显示内容布局：时间 / 日期 / 星期是一个圆角分组中的三行，名称左对齐、开关右对齐，不再分三列横向铺开。
- 时间新增独立侧栏页；当前顺序为外观 / 时间 / 交互 / 陪伴 / 插件 / 通用，插件入口同步修正索引。
- 数字字体提供默认 Segoe UI Variable Display、书卷 Cambria、几何 Bahnschrift、等宽 Consolas。只改变胶囊、小展开的时间数字；不改歌曲、日期、星期、表盘与插件文本。使用已安装系统字体，不随包分发字体。
- ClockFontId 新字段有旧配置默认值、非法值归一化、保存时的并发合并。字体参与原生文本缓存和时钟内容缓存，切换不必等到下一分钟。
- 原生 ABI 结构与版本号保持 V2；新增 capability 位 16 和时钟专用 flags 0x100/0x200/0x300，拒绝旧 DLL 和非时钟角色误用。发布时 managed/native 成对更新。
- 开关按 [Shoh2008 的表情滑动开关](https://uiverse.io/Shoh2008/average-monkey-56) 的设计意图原生重做：关闭是平静眼睛，开启是开心弯眼，220ms 可打断滑动。没有复制其 CSS；源码请求遭站点拦截，不宣称逐像素移植。
- 原生 ToggleSwitch 仍是唯一输入、键盘与 UIA 状态源；可视层不接收输入。禁用态、键盘焦点、按压、取消、减少动画与高对比回退均有处理。
- 左上接入用户提供的 S 形 Logo 原图和 GlassDesk 名称，资源随编译、发布输出复制。
- 保留侧栏布局，恢复浅色材质层次：淡灰画布、白色圆角分组、局部细分隔、蓝色选中态、半透明侧栏。系统 Acrylic 不支持时有底色回退。字体和形式选择统一成无默认绿色圆点的选项卡。

参考分工：[Apple Settings](https://developer.apple.com/design/human-interface-guidelines/settings) 用于分类与设置层级，[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials) 用于背景与内容表面的分离，Uiverse 用于表情与滑动反馈；不复制 Apple 专有图形，也不把网页控件嵌进 WinUI。

## 实际完成

- 顶部悬浮标签改为标准 NavigationView 侧栏；外观/交互/陪伴/插件/通用五类及顺序不变。
- 完整常规窗口替代“两块独立窗口区域”，不再调用旧 HRGN 遮罩与无边框配置。使用系统标题栏、系统窗口按钮。
- 普通设置采用单列、轻分隔；滑块在宽窗口左名称右控件，窄时移到下一行。移除普通卡片的填充/圆角套层。
- 仅当前设置页参与可见布局与输入；每页保留自己的控件和滚动位置。切页使用短淡入，隐藏时停止过渡。
- 陪伴页使用共享角色轮廓显示原生/猫娘/恶魔选项；新增紧凑预设色，保留 HEX 输入与折叠的完整 ColorPicker。
- 外观页中的布局预览纠正为**左侧圆形陪伴球、右侧时间**。200×52 逻辑尺寸、角色轮廓、25 DIP 时间角色、时间/日期/星期组合与现有组件对齐。
- 这个小预览明确标为布局预览；不捕获桌面、不运行液态玻璃，也不假装是实际磨砂截图。调整真实材质仍由原来的桌面组件显示。
- 透明度方向、保存合并、颜色预览代次、位置字段合并、插件配置与工具、诊断、快捷键捕获及错误处理保留。
- 页脚区分保存中、已保存与保存失败；较旧请求完成时如仍有新请求待存，继续显示保存中。
- 预设颜色选择会结束未提交的 HEX 草稿；切换形式仍保留现有颜色。
- 原生设置局部标题使用 24/32，继续经过系统 A 字体与中拉文处理；未修改全局/native 字体角色表。

## 建议先看这些

1. 侧栏、行间距和控件对齐是否舒服。
2. 外观页的预览是否与你的实际圆形陪伴球 + 时间结构一致。
3. 陪伴页的三个形式、预设色、HEX、更多颜色，能否顺畅修改。
4. 缩小窗口或高 DPI 时，滑块、插件设置和通用页能否滚动到最后。
5. 切页后回来是否保留滚动位置；关闭设置只隐藏，通用页退出才结束程序。

遇到问题直接给实际截图与操作顺序；下一轮按实测反馈修，不要求先跑复杂测试。
