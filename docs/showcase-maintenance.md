# 白底展示页维护说明

这份说明用于以后继续修改官网与 README 演示。它不是应用功能规范；不要把网页演示按钮连接到本机播放器，也不要为修改宣传页改变真实桌面组件。

## 文件位置

| 文件 | 作用 |
| --- | --- |
| `docs/index.html` | 完整网页：白底布局、音乐小展开、鼠标跟随、眨眼和演示播放控件。CSS / JavaScript 都在同一个文件中，不依赖在线字体或前端框架。 |
| `docs/images/logo.png` | 品牌标志，同时用作网页演示封面。 |
| `docs/images/favicon.png` | 32 × 32 网页图标；与 256 × 256 的网页标志均提取自已有应用 ICO，不重新设计品牌。高分辨率原稿仍在应用 Assets 中。 |
| `docs/images/peek.gif` | README 使用的白底动图，560 × 320，48 帧、约 12 fps、循环播放。 |
| `docs/images/peek.png` | 静态备用图，用于减少动态偏好。 |
| `README.md` | GitHub 应用介绍，引用上述图片并链接到展示页与安装包。 |
| `docs/.nojekyll` | GitHub Pages 静态文件标记。 |

## 本地预览

直接用 Edge / Chrome 打开 `docs/index.html` 即可，无需启动应用或服务器。它需要与 `images` 文件夹一起保存，不能只拷贝 HTML 后删除图片。

目前仅展示音乐小展开：顶部陪伴球与时间，下方封面、曲名和播放控制。没有设置、首页或小组件大图。页面强制浅色；背景为纯白，组件只保留轻微阴影。演示音乐是虚构曲目，不播放声音。

## 修改入口

- 文案与下载地址：修改 HTML 的正文、链接及页面描述。当前首次发布为 `v0.1.0`，不因修改网页自动升级应用版本。
- 排版与材质：修改 `<style>` 中的 `.hero`、`.peek`、`.peek-head`、`.metadata`、`.transport`。小展开逻辑尺寸为 320 × 176；桌面网页放大展示，窄屏通过媒体查询适配。
- 陪伴互动：修改末尾脚本。眼神只在演示区域内跟随，离开归中；点击短暂变开心表情；空闲自然眨眼。尊重 `prefers-reduced-motion`，不加入重粒子或连续背景渲染。
- 演示切歌：`titles` 数组提供虚构曲目；按钮只更新网页状态。真实应用的音乐能力以应用代码为准。

## 更新 README 动图

网页内置确定性导出入口，避免用录屏把浏览器边框或黑底带进来：

1. 用浏览器打开 `docs/index.html?capture=1`，使用 560 × 320 的视口。页面只保留白底小展开画布。
2. 自动化浏览器依次执行 `window.GlassDeskShowcase.renderAt(t)`，其中 `t = 帧序号 / 12`，帧序号从 0 到 47。
3. 每次执行后截取 `.demo-frame` 元素；第一帧保存为 `docs/images/peek.png`。
4. 将 48 帧编码为循环 GIF，使用统一调色板、纯白背景和约 83 毫秒帧时长，输出 `docs/images/peek.gif`。不要把原来带灰底或黑角的应用截图重新塞回 README。
5. 检查动图确实包含眼神移动与一次眨眼，白色四角没有变灰；尽量控制在 1 MB 内。当前文件约 125 KB。

`renderAt` 是宣传素材导出接口，和真实应用渲染没有耦合。若改变网页结构，记得同时更新该接口。

## 简单检查与发布

- 分别检查桌面宽度 1280、手机宽度 390、小屏宽度 320：没有水平滚动，文字和播放按钮不被裁切。
- 检查上一首 / 下一首、播放状态、点击陪伴球和移出后的眼神归中；检查键盘焦点以及系统“减少动态”。
- README 只引用当前动图及静态备用图，下载链接的文件名与 GitHub Release 附件一致。
- GitHub Pages 使用 `main` 分支的 `/docs`，地址为 <https://sheng-awa.github.io/GlassDesk/>。提交网页与资源后，等待 Pages 部署成功再检查线上页面。
- 同步到本地交付目录时，保留 `docs/index.html`、本说明和整个必要的 `docs/images` 资源集；安装包同样可携带这些静态文件。不要把浏览器自动化缓存、临时帧和构建日志打包进去。

实际应用的版本、安装包签名、音乐兼容性与性能需要分别验证，不能通过网页预览推断。
