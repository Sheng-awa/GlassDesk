## 二、必须照此实现的视觉和交互规格

### 2.1 全局视觉约束

所有布局尺寸使用 DIP，输入检测转换为对应显示器的物理坐标。不得把截图中的像素尺寸直接当作所有缩放比例下的尺寸。

统一基础参数：

| 项目 | 本轮默认值 |
|---|---|
| 基础白色染色透明度 | 保留 `0.24` |
| 基础模糊参数 | 保留 `20` |
| 展开主体圆角 | `24 DIP` |
| 音乐封面圆角 | `20 DIP` |
| 胶囊、导航、圆按钮圆角 | 按实际高度或尺寸计算 |
| 间距系统 | `4 / 8 / 12 / 16 / 24 DIP` |
| 字体 | Windows 原生字体，优先 Segoe UI Variable |
| 正文字色 | 深中性色，按背景保证对比度 |
| 数字 | 使用等宽数字特性，避免时间跳动造成横向抖动 |
| 动画位置过冲 | 默认关闭，避免越过文字及安全区域 |
| 身体形变 | 允许有限弹性，不用于放大文字或整个面板 |
| 简化动画 | 保留状态反馈，取消位移、形变及闲置游走 |

文字使用清晰的原生文本绘制。不要通过模糊文字、叠加多层文字阴影或挤出字形来制造立体感。

静止截图中也必须有明确层次：顶部导航、封面、曲目信息、播放操作依次形成阅读顺序。

### 2.2 三态尺寸与布局

胶囊和小展开沿用 0.2.0 的基本尺寸，避免本轮同时重做整个三态布局。

| 形态 | 尺寸或规则 |
|---|---|
| 时钟胶囊 | `200 × 52 DIP` |
| 音乐胶囊 | 宽 `208–296 DIP`，高 `52 DIP` |
| 时钟小展开 | `240 × 144 DIP` |
| 音乐小展开 | `320 × 176 DIP` |
| 有音乐、无有效时间轴的大展开 | `360 × 476 DIP` |
| 有音乐、有有效时间轴的大展开 | `360 × 512 DIP` |
| 未连接音乐的大展开 | `360 × 300 DIP` |

以上是本轮首个原生版本的实施尺寸。执行者不得自行改成全屏面板、横向仪表盘或 Dock。

显示器工作区不足时：

1. 保持顶部导航可见。
2. 保持播放主操作可访问。
3. 正文进入有边界的垂直滚动区域。
4. 不缩小字体来强行容纳全部内容。
5. 不允许窗口下沿或设置控件被裁切到屏幕外。

音乐大展开采用以下布局基准，坐标从组件内容区域左上角计算：

| 元素 | 布局 |
|---|---|
| 顶部导航 | 中心对齐，顶部 `12`，展开后 `288 × 48` |
| 封面 | `192 × 192`，水平居中，顶部 `88` |
| 歌名 | 顶部 `296`，左右各 `28`，单行省略，约 `17 DIP` 半粗 |
| 歌手 | 顶部 `324`，单行省略，约 `12 DIP` |
| 真实波浪条 | 顶部 `350`，约 `88 × 20`，居中 |
| 有效时间轴 | 顶部 `386`，宽 `248`，居中 |
| 时间轴文字 | 顶部 `402`，与时间轴两端对齐 |
| 无时间轴时的播放按钮 | 顶部 `398` |
| 有时间轴时的播放按钮 | 顶部 `434` |
| 主播放按钮 | `56 × 56`，水平居中 |
| 上一首、下一首 | 各 `44 × 44`，对称分布 |
| 设置入口 | 右下方低强调图标，实际命中范围至少 `32 × 32` |
| 既有插件内容入口 | 存在时保留在左下方，不与播放按钮争夺重心 |

主播放按钮中心、封面中心、标题中心和波浪条中心共用同一条垂直轴。

长歌名、长歌手、多语言文本采用省略与可访问名称处理，不自动缩成很小的字体，不在静止状态持续跑马灯。

无有效时间轴时，完整移除时间轴占位。不得绘制虚假进度条。

未连接音乐的大展开：

- 顶部导航照常存在。
- 中间使用小型中性音乐占位图形和简短标题。
- 保留用户主动点击的“打开音乐”入口。
- 不再把“尚未连接音乐”“播放后自动连接”等检测说明做成主视觉。
- 连接状态、能力说明和重新连接保留在设置。
- 不自动启动音乐应用。

### 2.4 两层悬停与一次点击的状态机

导航状态至少区分：

```text
Collapsed
HoverPending
Opening
Open
ClosePending
Closing
```

同时分别保存：

```text
OpenSequence
HoveredItemId
SelectedPreviewItemId
IntroConsumed
PointerCaptureOwner
```

不得把“悬停项”和“已选中项”存入同一个字段。

固定时序：

| 行为 | 时间 |
|---|---|
| 外层导航悬停确认 | `100 ms` |
| 外层展开 | `220 ms` |
| 内层项目放大与标签响应 | `160 ms` |
| 共享底板移动 | 约 `180 ms` 收敛 |
| 离开导航后的收起等待 | `300 ms` |
| 普通收起动画 | `220 ms` |

事件处理：

| 事件 | 必须发生的结果 |
|---|---|
| 指针进入外层导航 | 开始 100 ms 等待 |
| 等待期间离开 | 取消等待，不展开 |
| 等待完成且仍在内部 | 展开导航；首次触发时让陪伴球离开 |
| 指针进入内部项目 | 标签和邻近条形响应，不提交选中 |
| 点击内部项目 | 提交视觉选中项，不改变音乐正文 |
| 从外壳移动到子项 | 视为仍在同一导航中 |
| 从一个子项移动到另一个 | 连续更新悬停效果，不重新收起 |
| 离开整个导航 | 启动 300 ms 收起等待 |
| 等待期间重新进入 | 取消收起，从当前动画状态继续 |
| 导航收起 | 显示当前选中标签，不让陪伴球重新藏回 |
| 大展开关闭 | 取消本次打开的全部延迟任务 |

两次悬停的含义必须保留：

1. 外层悬停打开导航。
2. 内层悬停放大项目、显示文字。
3. 点击才提交视觉选中项。

当导航在指针下方展开、项目随布局出现时，要主动重新计算悬停项目，不能要求用户先移出再移入才能触发第二层效果。

### 2.5 导航的条形、标签与命中区域

- 收起宽度 `104 DIP`，展开宽度 `288 DIP`，高度始终 `48 DIP`。
- 展开时设置五个稳定的逻辑命中单元。
- 命中单元不随条形放大、底板移动或阴影变化而缩放。
- 未强调项目使用短竖条；邻近指针的项目逐级增高。
- 当前悬停项目显示约 `64 × 32 DIP` 的圆角文字标签。
- 没有悬停项目时，文字标签回到已选中项目。
- 使用一个共享强调底板，避免每个项目各自弹出一块白色背景。
- 文字位置、条形中心和底板中心保持对齐。
- 悬停预览底板移动时，`SelectedPreviewItemId` 不变。
- 视觉放大不得扩大真实命中区域，避免左右相邻项来回抢占指针。

### 2.6 每次打开大展开时的陪伴出场

这是大展开独有的出场行为，不复制到设置窗口。

进入一个新的 Details 打开周期时：

1. `OpenSequence` 增加。
2. 视觉选中项重置为音乐。
3. 陪伴启用时，将同一个陪伴实例引导到导航的出场位置。
4. 展示双眼和少量头部边缘，使眼睛在各种身体颜色下均清楚。
5. 设置 `IntroConsumed=false`。

首次外层悬停完成后：

1. 立即将 `IntroConsumed` 设为 `true`。
2. 陪伴离开导航，前往最近的安全前景位置。
3. 导航同时展开。
4. 当前打开周期内，即使指针离开、导航收起，也不能重新执行导航躲藏。

补充规则：

- 点击导航项目不能重置出场。
- 修改皮肤或颜色不能重置出场。
- 陪伴关闭时，收起导航直接展示“音乐”等正常标签。
- 陪伴在当前大展开中被重新启用时，直接出现在安全前景位置；不补播本次出场。
- 出场尚未完成就发生悬停时，从当前姿态直接离开，旧出场回调不得再次把角色拉回导航。
- 所有延迟回调都校验 `OpenSequence`。
- 始终只使用一个角色实例，不创建“导航里的眼睛”和“外面的球”两个活动角色。

|---|---|

| 在外部按下鼠标右键 | 是，外部右键操作仍正常发生 |
| 在外部按下鼠标中键 | 是 |

| 点击组件实际阴影 | 是 |
| 点击圆角外透明区域 | 是 |
| 点击设置窗口 | 是，设置属于组件范围外 |
| 点击组件自己打开且属于组件交互的弹出层 | 否 |

“内部”按当前实际显示的形状判断，不按整个外接矩形判断。

输入技术方案固定为：

- 在 Details 可见期间，使用专用线程安装 `WH_MOUSE_LL`。
- 线程具有消息循环。
- 回调只读取屏幕坐标、按钮、打开代次和不可变几何快照。
- 回调立即向后传递，不执行媒体操作、文件读写、渲染或跨线程等待。
- UI 线程收到外部按下通知后，再调用统一收起命令。
- 不使用全屏透明窗口。
- 不吞掉原事件，不模拟补发点击，不抢焦点。
- 不安装全局键盘钩子。
- 不一律丢弃带注入标记的鼠标输入，否则辅助输入和自动化验证可能失效。

该实现依据 Windows 对低级鼠标钩子的线程和回调要求设计。[Microsoft LowLevelMouseProc 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)

必须处理以下竞态：

- 收起后重新打开，旧通知不得关闭新面板。
- 组件移动或变形后，使用事件发生时的几何快照判断。
- 内部滑块或拖动拥有捕获权时，外部释放不得被当作外部点击。
- 收起后清除导航延迟和旧悬停状态，避免马上自动重新展开。
- 隐藏、退出、销毁及异常清理时卸载钩子并结束线程。
- 钩子安装失败时保留托盘收起操作，并在诊断中记录失败；不得偷偷改回右上角按钮。

## 三、陪伴系统、配置、模块接口与运行约束

### 3.1 陪伴身体与两种形式

陪伴球是软液体角色，圆形是默认静止形态。

本轮必须实现：

| 姿态 | 用途 |
|---|---|
| 近圆形 | 默认静止 |
| 横向轻微拉伸 | 起步、移动 |
| 轻微压扁 | 按压、落位 |
| 柔软水滴 | 改变方向或探头 |
| 局部探头 | 封面边缘躲藏 |

身体的形变、双眼、眼睑、耳朵和影子必须使用同一姿态来源。

禁止只对一个固定圆形做整体缩放后，宣称已经完成液态形态。

形式定义：

| 显示名称 | 稳定 ID | 视觉规则 |
|---|---|---|
| 原生 | `glassdesk.orb.original` | 软身体和原有双眼 |
| 猫娘 | `glassdesk.orb.cat-ear` | 同一身体、同一双眼，加两个同色小猫耳 |

猫娘形式：

- 耳朵与身体使用完全相同的颜色。
- 不增加粉色耳内、头发、尾巴、衣服或额外五官。
- 耳高约为普通身体直径的 `20%–22%`。
- 耳朵与身体轮廓连续连接。
- 形变时耳朵跟随对应头部位置。
- 安全区域、遮挡和阴影都按包含耳朵的完整轮廓计算。

### 3.2 矢量实现方式

现有项目已经具备 `NativeWidgetHost.CreatePolygonPath` 和路径动画能力。沿用这条原生 Composition 路线，不增加另一套渲染框架。

实施步骤：

1. 将陪伴身体由固定椭圆改为 `CompositionPathGeometry`。
2. 使用固定数量、固定顺序的轮廓点，建议统一为 32 点。
3. 原生、猫耳和不同形变保持相同路径拓扑。
4. 通过现有原生路径创建能力生成圆滑轮廓。
5. 使用 Composition 路径关键帧完成姿态过渡。
6. 复用已有播放图标的“从当前值开始”动画方式。
7. 为身体、裁切和阴影提供一致轮廓。
8. 缓存常用姿态路径，禁止每帧重新分配整套几何对象。

必须替换当前仅覆盖椭圆的面部裁切。否则新增耳朵会被旧裁切切掉。

身体中心是放置锚点，包含耳朵的视觉外接框是碰撞边界。切换形式时保持身体锚点，不因耳朵出现而让整个角色突然上下跳动。

### 3.3 表情逻辑的保留

继续保留已有：

- 展开回应；
- 指针接近回应；
- 按压、拖动、释放回应；
- 切歌、播放、暂停回应；
- 不规则眨眼；
- 视线跟随；
- 眼睛颜色自动适配。

不重新加入已经移除的固定 8 秒表情轮播。

颜色、形式、位置和表情是独立维度：

- 换颜色不重置眨眼计时。
- 换形式不重置角色位置。
- 表情更新不恢复旧颜色。
- 活动位置更新不清空表情。
- 每个维度只能由一个模块负责最终状态。

### 3.4 前景活动与安全区域

活动范围：

| 形态 | 活动方式 |
|---|---|
| Capsule | 保留稳定位置与现有跟随表现，不自动游走 |
| Peek | 在安全前景区域连续活动，可使用音乐封面躲藏 |
| Details | 在安全前景区域连续活动，另有一次导航出场 |

取消整个内容背面的漫游。

允许局部躲藏的对象，本轮只注册：

1. 大展开顶部导航的出场位置；
2. 小展开和大展开中真实显示的音乐封面边缘。

不允许随意把文字卡片、播放按钮、进度条或整张面板当成遮挡物。

安全区域由当前实际布局计算，至少排除：

- 文字实际占用范围；
- 所有按钮命中范围；
- 滑块及拖动范围；
- 真实波浪条范围；
- 顶部导航；
- 封面；
- 当前弹出层；
- 外壳圆角之外的区域。

保护范围向外增加 `8 DIP` 间距，并计入角色耳朵、变形和可见阴影的边界。

布局必须留出至少一个可靠的前景停留区域。该区域只作为无可用路径时的回退，不把正常活动重新限制为几个固定落点。

### 3.5 连续移动算法

采用轻量二维路径规划，不引入物理引擎。

固定算法：

1. 布局变化或请求新目标时，生成约 `8 DIP` 网格的可用区域。
2. 根据角色完整视觉边界扩张障碍。
3. 确定当前位置所属的可达连通区域。
4. 在该区域中随机选择目标，并添加网格内偏移，使落点具有连续变化。
5. 使用 A* 寻路。
6. 做直线可见性简化。
7. 对转角做小半径平滑，并再次检测碰撞。
8. 平滑后不安全时保留安全折线，并在转角降低速度。
9. 从当前真实位置和速度重定向。

移动时长按距离计算，限制在约 `450–900 ms`。位置使用无过冲的运动，身体允许轻微形变。

闲置活动规则：

- 每次动作结束后，随机等待 `12–20 秒`。
- 一次等待最多触发一次移动。
- 有可用封面躲藏点时，默认约 30% 的闲置选择进入探头状态，其余选择前景落点。
- 指针按压、拖动、滑块操作期间不自动移动。
- 已处于探头躲藏时暂停闲置游走，等待用户点击或布局改变。
- 组件隐藏、陪伴关闭、简化动画启用时停止闲置移动。
- 不添加永久 60 Hz 角色循环；运动期间使用现有调度，静止时停止位置更新。

找不到安全路径时：

- 当前位置仍安全：停留。
- 当前位置因布局改变失效：就近放到安全前景位置。
- 没有躲藏点：保持前景可见。
- 不跨过文字或播放按钮来维持动画连续。

### 3.6 封面探头躲藏

探头状态必须同时满足：

- 遮挡物当前实际存在；
- 身体只有部分被封面遮挡；
- 两只眼睛完整可见；
- 眼睛周围保留少量头部颜色，保证对比度；
- 耳朵不会被外壳无意裁断；
- 可见部分有真实命中区域。

实现采用角色自己的局部遮挡裁切，不把整个角色层放到所有内容后面。

点击规则：

1. 指针按下时记录角色命中并取得本次点击所有权。
2. 同一次点击完成后，进入 `Revealing`。
3. 从当前姿态移动到同一可达区域内的无遮挡前景位置。
4. 恢复普通前景活动状态。
5. 本次点击不再传给封面、正文、播放命令或组件拖动。

可见区域提供适度命中扩展，目标约不小于 `28 × 20 DIP`；扩展必须限制在露出区域附近，不能把整张封面变成角色按钮。

可访问名称使用“让角色出来”或等义表达。

连续点击时只重定向同一个实例，不产生多个球、多个完成回调或重复媒体操作。

封面在躲藏期间消失、切歌替换或尺寸变化时，取消旧遮挡关系并回到安全前景位置。

### 3.7 自由颜色设置

陪伴页使用：

- 原生颜色选择器；
- RGB 不透明颜色；
- 十六进制输入框；
- 原生／猫娘形式选择器；
- 当前形式和颜色的静态预览。

不再把固定颜色按钮作为主要选色方式。

十六进制输入规则：

- 支持 `RRGGBB` 和 `#RRGGBB`。
- 规范显示为大写 `#RRGGBB`。
- 不接受 Alpha 通道。
- 输入尚未完整或非法时，不覆盖当前有效颜色。
- Enter 或失焦时提交有效输入。
- 无效输入保留简短就地反馈，不把角色重置成默认颜色。

更新策略：

- 拖动颜色选择器时，角色立即预览最新颜色。
- 磁盘保存使用 `250 ms` 防抖。
- 操作提交、设置隐藏和程序正常退出时立即刷入最后一次有效值。
- 快速换色采用最后一次有效选择。
- 不因换色重启插件。
- 不允许旧异步表情帧把颜色或形式改回去。

形式切换保留颜色；颜色切换保留形式；重启后两者都保留。

设置中的预览只是一张静态或受控的小样，不再生成第二个会自主游走的陪伴实例。

### 3.10 输入路由优先级

同一输入只能由一个主要操作拥有。

按以下顺序路由：

1. 已拥有捕获权的拖动或滑块。
2. 探头角色的露出操作。
3. 顶部导航。
4. 播放控制、时间轴和现有功能按钮。
5. 正文空白区域的拖动／展开操作。
6. 外部点击观察结果。

导航出场中的双眼属于导航入口，不执行封面探头的“点击出来”逻辑。

角色揭示、导航选择和媒体操作必须在主协调器调用通用 `HandlePointer` 之前完成消费判定。

禁止出现：

- 点击眼睛同时切歌；
- 点击导航同时开始拖动窗口；
- 滑块拖到外面导致收起；
- 内部按钮完成操作后又执行正文点击；
- 旧鼠标释放触发新打开周期的动作。

### 3.11 液态玻璃优化

保持现有路线：

```text
真实桌面 WGC
→ 采集子进程
→ GPU 共享纹理
→ 现有模糊及折射处理
→ 原生 Composition 合成
→ 清晰前景内容
```

本轮优化集中于：

- 圆角边缘的折射连续性；
- 轻微厚度和边缘高光；
- 中心与边缘的材质差异；
- 封面、文字和控制所在层的清晰度；
- 浅色、深色及复杂背景上的稳定表现。

运行约束：

- 保留用户手动启停。
- 默认仍关闭液态玻璃。
- 不根据游戏、GPU 负载或电量自动替用户切换。
- 继续遵守现有最高约 30 Hz 的采集限制。
- 不增加 CPU 截图循环或常规 CPU 像素读回。
- 不退回宿主内长期持有 WGC 的旧方案。
- 隐藏或关闭插件时，按照现有生命周期释放对应 worker。

必须隔离：

| 对象 | 预览处理 |
|---|---|
| 主配置 | 独立数据目录 |
| 插件及插件配置 | 独立目录，不自动复制正式插件 |
| 诊断与日志 | 写入预览目录 |

| 全局快捷键 | 禁止真实注册 |
| 标题和托盘 | 清楚标明 UI Preview |

预览身份生成规则：

1. 将数据目录解析为绝对路径。
2. 去除非根路径末尾的目录分隔符。
3. 按 Windows 路径大小写不敏感规则规范化。
4. 对规范路径求 SHA-256，取前 16 个十六进制字符。
5. 使用 `GlassDesk.UiPreview.<hash>` 作为实例命名空间。
6. Mutex、窗口标记、设置消息和退出消息全部由同一身份生成。

正式模式保持现有命名兼容。

以下命令语义必须成立：

```text
--ui-preview --data-dir=<A> --quit
```

只退出 A 预览实例，不能退出正式版或使用其他数据目录的预览实例。

系统集成隔离不能只做 UI 灰化：

- 预览启动时不注册用户保存的正式快捷键。
- 偏好更新、错误回滚、退出清理都不得修改正式启动项。
- 不调用“禁用启动项”来表示预览隔离，因为这可能删除正式版条目。
- 设置中相关控件禁用，并标注“预览版不修改系统启动和全局快捷键”。
- 音乐状态读取与用户主动点击的媒体操作继续可用。

启动异常日志：

- 已解析出预览目录时写入该目录。
- 参数解析失败但明确包含 `--ui-preview` 时，写入临时目录中的 `GlassDesk.UiPreview` 错误目录。
- 不再落入正式 `%LocalAppData%\GlassDesk`。
