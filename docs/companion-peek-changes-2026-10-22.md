## 修复依据与最终行为

### 1. 大展开顶部眼神

`DetailsChromeVisual` 原来只有静态的两只眼睛。这次在原来的胶囊内部增加独立 gaze 容器，眼睛一起轻移，身体和点击范围固定。鼠标在组件内移动时跟随，离开或丢失捕获时归中；禁用跟随、减少动态、隐藏窗口时复位。

横向最多 2.5 DIP、纵向最多 2 DIP，200 ms 平滑衔接，不追求机械地贴住鼠标。不增加逐帧画字/绘制 UI 的定时器；运动由 Windows.UI.Composition 执行。

同时修正 `UpdateContentTimers`：此前“不是胶囊”就清除 gaze，会与新增的大/小展开眼神打架。现在只是停止胶囊的全桌面鼠标轮询，展开形态继续接收窗口鼠标事件。

### 2. 导航眼睛归位与节奏

`HomeVisual` 原来的 `_yielded` 一经激活就保持 true，导致本次大展开内眼睛始终留在右下角。这次移除这个锁存状态，改为按导航当前展开状态选择中心或右下角。

- 悬停展开：离开后收回，眼睛归中。
- 点击固定展开：维持已有的再点折叠语义；固定时留角落，折叠后归中。
- 弧片展开 420 ms、收回 340 ms，展开错峰 45 ms；眼睛位置 400 ms；微小 gaze 200 ms。
- 从正在显示的位置接续动画，不反复从初始值重播。减少动态时直接呈现最终状态。
- 清除悬停时，即使没有改变 hover 区块，也复位细微 gaze。

### 3. 小展开封面

根因：封面共享层用 `HomePage ? 0 : …` 决定整体不透明度。记忆页面是首页时，小展开也被一起隐藏。

改为分别计算胶囊、小展开、音乐详情三个形态的权重，首页/小组件只抑制自己的 Details 音乐层。小展开保持封面；音乐层不会残留到小组件详情页。缺失来源封面时仍使用已有唱片 fallback，不生成假的网络封面。

### 4. 新小展开结构

音乐小展开从上一轮 **320×192 收紧为 320×176 DIP**，圆角仍为 24。去掉顶部公共浅色框及时间底板，保留整体玻璃窗口；封面与信息上移 8 DIP，播放行上移 12 DIP。其他五组基础形态尺寸不改。

| 区域 | 几何 / 行为 |
|---|---|
| 顶部 | 无公共背景条、无时间底板，直接放在整体玻璃材质上 |
| 陪伴脸 | 58×28；纯时间时 x79/y14，带日期辅助行时 x63/y16；两只眼睛，不在正文里游走 |
| 顶部时间 | 纯时间 x145/y15，宽 96；有辅助行时 x129/y10，宽 128。与脸保持 8 DIP 的布局间隙，整组居中 |
| 播放控制 | x86/138/190，y124；上一首/播放暂停/下一首各 44×44，能力缺失时禁用；绘制与命中共用同一高度常量 |
| 关闭陪伴时 | 时间区域按宽 96 / 128 居中，底部播放控制位置不变 |
| 封面 | x24/y64，48×48，圆角 14 |
| 曲名/歌手 | x88/y64；频谱开时宽 170，关时宽 208；沿用省略与中拉字体策略 |
| 频谱 | 保留 8 根，音乐小展开 x266/y72；胶囊中原来的位置与静息状态不改 |
| 日期辅助行 | 有配置才显示，在时间区域 y36，高 12，不占底部播放区域 |

文字背景取色也随布局同步调整：歌曲区域采样 y84，顶部时间采样 y28。已连接音乐时不再把不存在的白色时间底板计入可读性计算；未连接时保留原有时间底板及对应计算。没有为了去框将时间强制改成白色。

未连接音乐时仍为 240×144，顶部显示陪伴脸，下方时间和打开网易云入口。点击播放键不会穿透为展开；点击正文继续进入大展开。原有页面记忆规则继续保留。
