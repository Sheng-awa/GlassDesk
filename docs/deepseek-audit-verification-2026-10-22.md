# DeepSeek 审查复核与本轮修复记录

日期：2026-10-22  
对象：`docs/current-code-audit-2026-10-22.md`，以及 GlassDesk 当前磁盘源码。  
范围：先修现有运行缺陷；保留页面记忆、现有图标和设置设计。不创建安装器、不决定正式版号、不提交或重置已有 Git 改动。

## 结论

**原报告有有效发现，也有两条重要结论与当前代码/其引用截图相矛盾，不能整份照单全收。**

本轮确认并修复：目录预览内容缓存遗漏、外观缓存遗漏、取消退出后的观察器恢复、首页隐藏后的眼神偏移、无动作的 UIA“按钮”。另外修补了返回箭头在深色材质上的颜色与悬停反馈，并纠正陪伴把手的可访问名称。

原报告关于“返回箭头完全没有绘制”“引用截图里首页标签为深色”的断言不成立。未提交源码、视觉尚未人工验收、真实旧插件尚未测试等是交付状态或证据边界，不能全部写成当前已确认的产品 bug。

## 重要证据与依据

### 1. 为什么说两个 P1 结论不可靠

返回箭头并不是本轮新增的：修改前的 `WidgetScene.DrawDetails` 就通过 E72B 字形在 (24, 20) 绘制了 18 DIP 箭头。原报告以“搜索 HomeBack 没有找到绘制”为依据，遗漏了**绘制使用字形、命中使用动作 ID**这两条不同路径。

当前关联代码：
- [返回箭头绘制](../../src/GlassDesk.App/WidgetScene.cs)：DrawDetails。
- [返回路由](../../src/GlassDesk.App/GlassDeskCoordinator.cs)：OnPointer 的 HomeBack 分支。
- [点击目标](../../src/GlassDesk.App/WidgetScene.cs)：BuildControls 中的“返回首页”。

首页标签的原报告截图：
[报告引用的 current4 首页原图](../../artifacts/audit/current-review-2026-10-22/screens/current4-01-home-1-GlassDesk-UI-Preview-0-3-0-preview-3-540x768.png)。

这张图实际是**深灰外壳 + 浅色应用名称**。源码 [WidgetScene.Home.cs](../../src/GlassDesk.App/WidgetScene.Home.cs) 也把材质选择 `_lightText` 传给标签 ink。二者都不能支持“默认仍是暗字”的结论。

但外围四点取色只是估计，不是最终合成像素的对比测量。因此本轮结论是“报告该项证据错误”，而非“所有背景对比都已经达标”。

### 2. 文件列表缓存为什么会显示与动作不一致

旧 key 把整个 preview 插进字符串，Entries 只贡献集合类型描述。目录名称、路径、状态相同但里面文件变了时，视觉 surface 可能复用旧文本，而点击目标来自新列表。

本轮 [HomePresentationState.cs](../../src/GlassDesk.App/HomePresentationState.cs) 的 HomePopupRenderKey 保存：
- 文件夹索引、名称、路径、状态、错误消息、条目数量；
- 当前实际显示的前三项的名称、路径、是否文件夹，按值快照；
- 弹层尺寸、箭头锚点、按下项；
- 主/次 ink、背景、高对比、DPI。

它不依赖集合引用相等，也不依赖 ToString；相同内容的新数组仍可复用，原集合被修改也不会改变已经缓存的旧 key。

[HomePopupChecks.cs](../../tests/GlassDesk.Core.Tests/HomePopupChecks.cs) 覆盖：相同内容复用、同路径改名、路径改变、文件/目录改变、空/错误状态、secondary/highContrast/DPI 变化。

只快照实际显示的前三项是有意的：气泡仅展示前三项，点击也仅为前三项建立目标；第四项之后的内容不影响当前画面，不需要每次序列化整个目录。

### 3. 取消退出的恢复修了什么

[GlassDeskCoordinator.cs](../../src/GlassDesk.App/GlassDeskCoordinator.cs) 的 Quit 在确认前停止了计时器并撤销 outside 观察。取消后原来只调用 Render；Render 能恢复部分内容任务，但不会必然重新挂回 outside 或触发一次文字探测。

本轮取消分支恢复：
1. 设置窗口与当前画面；
2. outside 当前详情几何注册；
3. 延迟文字材质适配；
4. 按当前状态唤醒动画/陪伴调度；
5. 若页面记忆仍待保存，重新安排保存；
6. 更新插件场景并通知设置状态。

Render 中原有的 UpdateContentTimers / ReconcileWidgetBoard 继续恢复音乐状态补读、时间、进度与组件刷新。没有强行把所有计时器全部启动，隐藏场景仍遵循按需调度。

**未实机触发保存失败对话框**：这项完成的是代码修复与编译复核，不能写成用户实际点“否”已验收。

### 4. 测试重试的边界

[WidgetStoreChecks.cs](../../tests/GlassDesk.PlatformChecks/WidgetStoreChecks.cs)：
- 只对 HRESULT 低位为 2 / 3 / 32 / 33 的短暂打开失败重试；
- 每轮读取最多 5 次尝试，退避为 1 / 2 / 4 / 8 ms；
- JSON 解析错误不重试、不吞掉；
- 重试耗尽或其他 IO 错误仍失败；
- 仍要求读取到可解析的完整结构、最终配置正确、没有遗留临时文件；
- 失败消息包含 HRESULT、重试次数和实际异常；首次读成功的等待增加 5 秒上限，避免无期限挂住检查。

没有降低产品文件写入的原子性，也没有因为偶发失败改成覆盖重试直到通过。

### 5. 无障碍语义与鼠标交互分离

[WidgetScene.Home.cs](../../src/GlassDesk.App/WidgetScene.Home.cs) 不再向 UIA 暴露没有动作的“文件夹预览”按钮；[WidgetScene.cs](../../src/GlassDesk.App/WidgetScene.cs) 在命中关闭气泡的背景前检查是否位于气泡内部，把内部空白路由成只消费鼠标的 HomePopupBody。

文件条目、打开文件夹、关闭预览仍是真实可调用操作。顶部陪伴把手原先名称“回首页（陪伴）”与实际收起行为不符，本轮在 [DetailsChromeVisual.cs](../../src/GlassDesk.App/DetailsChromeVisual.cs) 改为“收起为胶囊（陪伴）”。

## 试用与剩余边界

独立目录：[audit-bugfix-2026-10-22](../../artifacts/ui-preview/audit-bugfix-2026-10-22/)；入口为目录中的“启动试用版.lnk”。保留整个目录。没有自动启动本版、停止旧实例或覆盖原配置。

建议先做几步简单试用：
1. 同一文件夹气泡关闭后，在对应测试目录改名/新增/删除一项，再打开，看显示与点击是否一致。
2. 音乐/小组件页左上箭头：深浅背景可见，悬停有反馈，点击返回首页；顶部陪伴把手仍收起。
3. 开气泡后点内部空白、再点外部：前者保留，后者关闭且不启动背后应用。
4. 隐藏/收起再打开首页，看眼睛是否残留之前的偏移。
5. 若自然遇到保存失败并取消退出，确认外点收起与时钟/播放状态仍继续更新；不用为了本项强改真实配置权限。

仍保留的实际边界：
- 目录同步 OS 调用可能挂起：调用方会超时，每目录最多一个底层任务；未实现强杀 worker。
- 第三方进程内插件需要可信代码；没有 UI 线程亲和保证，真实旧插件兼容性不是此次基础检查能保证的。
- 外围取色不能证明所有复杂壁纸上的最终对比；白/深/低 tint/高对比/短工作区观感需要用户实际确认。
- 本机图标视觉面积、原创品牌资源、设置 UI 重做及正式交付继续另行处理，本轮没有擅自改方向。

这些是留下的边界或后续范围，不等于本次已经确认仍存在同等级 P1 产品故障。若人工试用复现新的异常，再依据具体操作和截图继续修复。
